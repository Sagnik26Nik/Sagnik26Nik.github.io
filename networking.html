Networking Concepts

DNS, HTTPS, IPv4/IPv6, CDN, TLS — the infrastructure powering this site.

🌐 DNS Resolution

DNS translates sagnik26nik.github.io into an IP address. GitHub Pages routes through Fastly's anycast CDN — the IP you get depends on your geographic location, minimizing latency worldwide.

Terminal — DNS lookup commands
# Look up IPv4 address
nslookup sagnik26nik.github.io
# → 185.199.108.153 (Fastly CDN node)

# Look up IPv6 address
nslookup -type=AAAA sagnik26nik.github.io
# → 2606:50c0:8000::153

# Full DNS trace
nslookup -debug sagnik26nik.github.io

# Trace the network path
tracert sagnik26nik.github.io       (Windows)
traceroute sagnik26nik.github.io    (Mac/Linux)

📡 IPv4 vs IPv6 — Dual Stack

This site supports both protocols simultaneously. IPv4 uses 32-bit addresses (≈4.3B total, nearly exhausted). IPv6 uses 128-bit addresses — practically unlimited. GitHub Pages / Fastly handles dual-stack routing automatically.

IPv4

185.199.108.153
  • 32-bit address
  • ~4.3B addresses
  • NAT required
  • Since 1983

IPv6

2606:50c0:8000::153
  • 128-bit address
  • 340 undecillion addresses
  • No NAT needed
  • Built-in IPSec
Test IPv6 connectivity
ping -6 sagnik26nik.github.io        (Windows)
ping6 sagnik26nik.github.io          (Mac/Linux)

# Check if your connection supports IPv6
curl -6 https://sagnik26nik.github.io -I

🔐 HTTP vs HTTPS

HTTP sends data as plaintext — anyone on the network can intercept it. HTTPS wraps HTTP in TLS (Transport Layer Security), encrypting all data. GitHub Pages enforces HTTPS with a permanent 301 redirect from HTTP.

❌ HTTP

  • Port 80
  • Plaintext — readable
  • No verification
  • Susceptible to MITM
  • No data integrity

✅ HTTPS (this site)

  • Port 443
  • TLS 1.3 encrypted
  • Certificate verified
  • MITM-resistant
  • Integrity guaranteed

⚡ CDN — Content Delivery Network

A CDN distributes copies of your site across global edge nodes. Requests are served from the nearest node instead of a single origin server — dramatically reducing latency. This site uses:

  • Fastly CDN — built into GitHub Pages, handles IPv4/IPv6
  • Cloudflare (optional) — additional DDoS protection + caching
  • cdnjs.cloudflare.com — DOMPurify library served from CDN edge

🖼️ Lazy Loading

Images below the viewport are not loaded until the user scrolls near them. This reduces initial page weight and improves Time to First Contentful Paint (FCP). We use both the native loading="lazy" attribute and an Intersection Observer for maximum browser compatibility.

HTML — native lazy loading
<!-- Native browser lazy loading (Chrome, Firefox, Edge, Safari) -->
<img src="image.jpg"
     loading="lazy"
     alt="Description"
     width="800" height="600" />
js/main.js — Intersection Observer fallback
// Handles older browsers that don't support loading="lazy"
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src;      // swap in real src
      observer.unobserve(img);        // stop watching
    }
  });
}, { rootMargin: '200px' });         // start 200px before viewport

// Apply to all lazy images
document.querySelectorAll('img[data-src]').forEach(img => {
  observer.observe(img);
});

🗜️ CSS & JS Minification

The GitHub Actions pipeline automatically minifies all CSS and JS files before deploying. This removes whitespace, comments, and shortens variable names — typically reducing file sizes by 60–75%.

.github/workflows/deploy.yml — minification step
- name: Minify CSS and JS
  run: |
    npm install -g clean-css-cli uglify-js

    # Minify CSS
    cleancss -o css/style.min.css css/style.css
    echo "CSS: $(wc -c < css/style.css) → $(wc -c < css/style.min.css) bytes"

    # Minify JS
    for f in js/main.js js/security.js js/monitor.js; do
      uglifyjs "$f" -o "${f%.js}.min.js" -c -m
      echo "JS: $f minified"
    done
